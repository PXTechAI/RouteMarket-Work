# Desktop 聊天冒烟验证

本流程用于验证 Desktop P0 的关键聊天链路，避免只用打包成功代替功能验证。

## 自动化冒烟

在仓库根目录运行：

```powershell
corepack pnpm test:chat-smoke
```

测试会在临时目录中完成以下真实本地操作：

1. 使用桌面访问令牌请求 Agent 列表并选择固定版本。
2. 创建带本机文件夹的项目和本地对话线程。
3. 发送带 Agent 快照的消息。
4. 接收模型流式 Tool Call。
5. 通过真实 `ProjectRegistry`、`ProjectChatToolRunner` 和本地文件读取执行器读取项目文件。
6. 把 Tool 结果返回给下一轮模型并接收最终回复。
7. 关闭并重新打开本地数据库，验证用户消息、最终回复、Agent ID 和版本能够恢复。

云端 Agent 与模型响应使用确定性协议夹具，不依赖开发者个人账户或外部网络；本地项目、
Tool 权限边界、文件读取和 SQLite 恢复使用正式运行时代码。

## 开发模式人工验收

发布候选前，还需要在 RouteMarket Core 的本地 Web（3000）和 API（3001）运行时执行：

1. 运行 `corepack pnpm dev`，确认窗口标题和顶栏显示“开发版”。
2. 完成网页登录或注册，确认 Desktop 自动进入工作区。
3. 创建并关联一个测试文件夹，选择一个允许文件读取的 Agent。
4. 发送明确要求读取文件的问题。
5. 确认界面依次出现用户消息、Tool 调用卡、完成状态和最终回复。
6. 关闭并重新启动 Desktop，确认同一项目恢复消息和 Agent 信息。
7. 移走测试文件夹并刷新，确认显示“文件夹丢失”、本地能力禁用且可以重新关联修复。

人工验收使用专门的测试项目，不能对真实工作目录执行写入或删除提示。
