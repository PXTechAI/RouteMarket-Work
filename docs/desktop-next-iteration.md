# RouteMarket Work Desktop 下一阶段开发清单

更新日期：2026-07-24

本文记录 Desktop V1 之后的产品决策、下一阶段开发顺序和验收标准。
Web 与 Desktop 可以共享 Agent、模型、Skill 和账户状态，但项目、文件夹
绑定及本地对话默认属于设备本地数据。

## 已确定的产品边界

### 登录与账户

- 未登录时显示覆盖整个窗口的登录/注册界面，不能进入工作区。
- 登录令牌需要安全持久化，优先使用操作系统凭据存储。
- 启动、恢复前台和固定周期刷新账户状态，及时同步封禁、会员、余额及权限。
- 本地缓存只用于离线展示，服务端账户状态恢复后必须覆盖缓存。

### 项目与文件夹

- 统一称为“项目”，不再使用“本地工作区”。
- 项目可以不关联文件夹，也可以关联一个本地文件夹。
- 关联后，Agent 默认把该文件夹作为文件读取、搜索和修改范围。
- 删除项目只删除 Desktop 中的项目记录、对话索引和绑定关系，不删除磁盘文件夹。
- Web 项目与 Desktop 项目默认不自动合并。未来通过用户主动“发布到云端”或
  “从云端创建本地副本”建立明确关系。

### 对话数据

- Desktop 对话默认仅保存在本机，不自动同步到云端。
- 云端只接收执行请求所需的最小上下文、所选 Agent/模型/Skill 快照和用量数据。
- 后续同步必须是显式动作，并向用户说明哪些消息、附件和项目元数据会上传。
- 删除本地对话不应删除云端 Agent、Skill 或账户记录。

### Agent、Skill 与执行能力

- Agent 定义从云端同步，包括稳定 ID、版本、头像、system prompt、默认模型、
  Skill 绑定和 Tool 权限。
- 每次本地对话固定使用一个 Agent 版本快照；云端有新版本时提示更新，不静默改变
  已有对话行为。
- Skill 是用户看到的能力；Tool 是模型调用的运行时函数；Connector 是凭据或服务
  配置；模型原生能力单独判断，不能混为一个设置。
- Desktop 可以执行本地文件、终端、浏览器、本地 MCP 等本地 Tool；云端 Agent
  只声明权限，不直接获得本地路径或凭据。

## 下一阶段优先级

### P0：可持续开发与可靠验证

- 固定 `pnpm dev` 为日常 UI 与逻辑测试入口，不要求每次生成安装包。
- 增加开发版、打包版的明显环境标识，避免误测旧的 `win-unpacked`。
- 修复并锁定开发窗口、任务栏、安装包和系统通知的品牌图标。
- 建立一条聊天真实冒烟测试：登录、选 Agent、发送消息、Tool 调用、最终回复、
  重启后恢复。
- 打包只用于发布候选验证；发布候选必须记录版本、构建时间、提交和 SHA-256。

### P0：登录与账户状态

- 实现全屏登录门禁和安全令牌持久化。
- 处理令牌过期、账号封禁、会员升级、余额变化和远端退出。
- 统一登录错误、网络离线、服务不可用和需要重新认证的用户提示。

### P0：本地项目生命周期

- 支持创建空项目、创建并关联文件夹、给现有项目关联或更换文件夹。
- 支持删除项目并明确提示“不会删除磁盘文件”。
- 展示失效文件夹、权限不足、磁盘移动后的修复入口。
- 为项目、文件夹绑定和对话建立稳定本地 ID，避免用路径作为主键。

### P1：对话与输入框对齐 Web

- 对齐 Agent 头像、名称、时间、Markdown、错误卡、Tool 调用卡和消息操作区。
- 输入框补齐 Agent 选择、模型选择、Skill 展示、附件、本地/云端执行环境和发送状态。
- 联网搜索保持“智能检索 / 模型原生检索 / 关闭”的一致语义。
- 智能检索使用官方搜索或账户首选 Connector；Desktop 不直接保存搜索 API Key。
- 增加消息编辑、重新生成、停止、重试、复制及长对话虚拟化。

### P1：Agent 与 Skill 同步

- 拉取官方 Agent 和用户 Agent，缓存头像及版本信息。
- 使用版本快照启动对话，并提供“有新版本”提示和更新动作。
- 明确 Desktop 支持的 Skill 子集；不可用能力显示原因，不静默隐藏。
- 本地 Tool 调用必须经过权限检查、风险分级和确认流程。

### P1：本地数据与隐私

- 使用可迁移的本地数据库保存项目、对话、消息、运行状态和 Agent 快照。
- 对令牌、Connector 引用和敏感配置使用系统安全存储，不写入普通 JSON。
- 提供本地数据目录、占用空间、导出、清空和崩溃恢复能力。
- 日志默认脱敏，不记录完整提示词、文件内容、令牌和本地绝对路径。

### P2：界面与主题

- 左侧栏与主区域使用统一 light/dark 主题，不混用固定深色侧栏。
- 主题切换放在侧栏底部用户菜单内，菜单向上展开。
- 侧栏支持展开/收起，并保存窗口级偏好。
- 统一空状态、加载骨架、离线状态和 Worker 连接状态。

### P2：发布与更新

- 建立正式自动更新渠道、灰度策略、签名和回滚方案。
- 区分开发、测试、生产 API 地址，生产包不得包含本地开发地址。
- 增加安装、覆盖升级、卸载、旧数据迁移和自动更新回归测试。

## 验收原则

- 日常功能修改必须先通过开发模式验证，不以“打包成功”代替功能验证。
- 涉及本地文件的删除操作必须验证不会删除用户磁盘内容。
- 涉及云端同步的功能必须显式、可撤销并可解释上传范围。
- Agent 行为必须能够追溯到确定的版本、system prompt、Skill 和 Tool 权限。
- UI 对齐以交互语义和组件结构为准，不复制 Web 中不适合桌面的导航和云端数据假设。
